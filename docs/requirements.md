# Offline Package Sync — 需求规格说明书

> v0.2 精简基线｜2026-10-11｜由 v0.1 等义压缩；不变更已确认需求或优先级。技术可行性与实测状态见 `technical-validation.md`。

## 1. 目标、边界和使用场景

**目标**：在公司“外网文件可依规进入内网、内网数据不得外传”的隔离约束下，完成 `PyPI/npm 单包/多包/项目依赖 → 按目标环境解析并下载 → 可校验 ZIP Bundle → 人工合规传输 → 内网 Nexus Hosted 批量导入与审计`。减少人工查找传递依赖；支持 Web 用户与 Coding Agent，保留错误、缺口和可追溯性。

**成功标准**：受支持且可获取的依赖可自动收集和导入；内网 Web/CLI 同一业务逻辑与任务审计；已存在且内容一致的制品跳过，不一致则报告冲突；不把“下载成功”或“已发布”冒充“已验证离线可安装”。

**运行环境/规模**：外网 Windows/Linux 桌面单机（本地 Web UI + CLI）；内网 Linux 无头中心服务（Web UI + HTTP API）、Windows/Linux 用户端（浏览器 + 轻量远程 CLI）；科室约 **15 人**。Nexus **本地账号密码**登录，MVP 暂定全部使用者拥有目标 Hosted 仓库上传权限，实际按 Nexus 权限执行；无需人工同步第二套用户体系，不设审批。内网 CLI 仅调用中心服务，不自行上传 Nexus；两端不跨区通信或共享数据库，文件只经现有合规渠道人工传入。Web UI 优先，Electron 后续评估。

**术语/语义**：目标环境 = Python 实现/版本/ABI/平台组合；依赖闭包 = 指定输入约束和目标环境下的递归依赖；发行文件 = Wheel/sdist 或 npm Registry tarball；Bundle = 可传输发行文件、Manifest、哈希及告警的 ZIP；导入任务 = 持久化、可追踪的 Nexus 检查与发布操作；“尽力而为”允许明确标识的不完整结果。完整性**只针对选定目标环境及输入约束**，不涉及所有历史版本或全仓镜像。

**典型场景**：按单包/多包与版本约束同步；`requirements.txt`/`pyproject.toml` 或 `package.json`/`package-lock.json` 项目同步；同一 Bundle 多 Python 环境共享物理文件；内网用户上传、预览、确认、执行、查询；Agent 非交互提交/等待/查报告；缓存复用和重复导入跳过。

## 2. MVP 功能需求（保留原始编号）

优先级：`P0` 初版必备；`P1` 稳定后增强；`P2` 不纳入初版。

### 2.1 外网输入、目标环境

| ID | 级别 | 必要行为 |
| --- | --- | --- |
| EXT-01 | P0 | 输入单个/多个 PyPI 或 npm 包，支持精确版本与对应生态版本范围。 |
| EXT-02 | P0 | 导入 Python `requirements.txt`、`pyproject.toml`，npm `package.json`、`package-lock.json`；Python lockfile 方言待验证。 |
| EXT-03 | P0 | 目标 Python 环境可设置解释器/实现、版本、ABI、平台，提供常用预设和高级自定义。 |
| EXT-04 | P0 | 一次选择多个目标环境，分别解析并跨环境去重发行文件。 |
| EXT-05 | P0 | 按**兼容标签集合**判断 Wheel 兼容性，不做文件名标签单点精确匹配。 |
| EXT-06 | P1 | 保存、命名、复用环境配置。 |

环境参考范围 **Python 3.9～3.14**，重点 CPython 3.9/3.12 × Windows/Linux；开放自定义但不得承诺任意环境都有可用发行文件。

### 2.2 依赖求解、收集与缓存

| ID | 级别 | 必要行为 |
| --- | --- | --- |
| EXT-07 | P0 | 递归求解直接和传递依赖，处理版本约束、环境 markers、extras/optional 等。 |
| EXT-08 | P0 | **普通包默认重新解析当前满足约束的版本**；允许切换复用历史/锁定结果。 |
| EXT-09 | P0 | **项目默认优先遵循受支持 lockfile**；允许显式重解析；无锁文件按项目声明求解并记录版本。 |
| EXT-10 | P0 | 记录约束、包版本、目标环境归属、依赖边，保证追溯。 |
| EXT-11 | P0 | 优先选目标兼容的已发布二进制或 npm tarball；校验完整性。 |
| EXT-12 | P0 | 本地持久化可验证文件身份的下载缓存，避免重复下载。 |
| EXT-13 | P0 | 缺 Wheel 时尽力收集 sdist 与可识别构建依赖；无法保证构建则报告风险。 |
| EXT-14 | P0 | npm 覆盖普通/peer/optional/平台依赖，明确报告额外下载、脚本及特殊源缺口。 |
| EXT-15 | P0 | 解析/下载失败明确包、环境、原因、影响范围，**不静默遗漏**。 |
| EXT-16 | P1 | 历史任务复用、重新解析对比、细粒度缓存维护。 |

**安全与版本策略**：默认不执行第三方安装/构建脚本；代码执行需求应列风险或另做受控扩展。普通包坚持版本优先，不能为取得旧 Wheel 而静默降级并宣称完整；动态元数据/构建依赖无法确认时必须显式标为不完整。

### 2.3 Bundle

| ID | 级别 | 必要行为 |
| --- | --- | --- |
| BND-01 | P0 | 生成单个可携带 ZIP，含发行文件、机器可读 Manifest、多环境求解结果、缺口报告。 |
| BND-02 | P0 | Manifest 包括格式版本、生态、规范化输入、环境、包/文件、来源、SHA-256、解析状态。 |
| BND-03 | P0 | 多环境共享文件仅存一份，保留环境到文件映射。 |
| BND-04 | P0 | 打包前与导入时分别检查存在性、文件哈希。 |
| BND-05 | P0 | 清晰区分已收集、有缺口、已验证离线可安装等状态。 |
| BND-06 | P1 | 超大 Bundle 分卷或外部文件存储。 |

Bundle 格式应具版本字段；具体 ZIP 结构与 JSON Schema 由架构/开发阶段定稿。

| ID | 级别 | 必要行为 |
| --- | --- | --- |
| IN-01 | P0 | 内网常驻服务统一提供 Web UI/HTTP API。 |
| IN-02 | P0 | 用 Nexus 本地账号校验身份，不另建需人工同步的账号体系。 |
| IN-03 | P0 | 已登录者可上传 Bundle；校验 ZIP 安全、Manifest、文件与目标仓库。 |
| IN-04 | P0 | 上传获得唯一任务 ID，异步执行，浏览器断开不影响任务查询。 |
| IN-05 | P0 | 执行前可预览包/文件数量、目标仓库、风险/缺口并确认导入。 |
| IN-06 | P0 | 按生态分别发布 PyPI/npm 到 Nexus Hosted。 |
| IN-07 | P0 | 发布前查远端；内容相同跳过，身份冲突而内容不同则报告并禁止覆盖。 |
| IN-08 | P0 | 任务和文件级进度、错误、有限重试、最终报告。 |
| IN-09 | P0 | 持久化任务及文件结果；重启识别中断，未完成不得误报成功。 |
| IN-10 | P0 | 统一记录 Web/CLI 操作者、时间、入口、仓库、Bundle ID/哈希、文件结果与操作状态。 |
| IN-11 | P0 | 用户仅看个人任务；授权维护者可查全局历史/审计。 |
| IN-12 | P1 | 取消、指定失败文件重试、可配并发与归档保留策略。 |

### 2.5 CLI、Agent 与本地 Web

| ID | 级别 | 必要行为 |
| --- | --- | --- |
| CLI-01 | P0 | Windows/Linux 内网轻量 CLI **只作为中心服务 API 客户端**。 |
| CLI-02 | P0 | 配置服务地址、登录、提交 Bundle、状态查询与报告获取。 |
| CLI-03 | P0 | 非交互执行、JSON 输出、稳定退出码，便于 Agent。 |

| CLI-06 | P1 | 任务列表、重试/取消、机器可读能力发现。 |
| UI-01 | P0 | 外网 Web 支持包/项目输入、环境设置、依赖预览、进度、告警、导出。 |
| UI-02 | P0 | 外网 CLI 等价覆盖核心解析/下载/导出，支持非交互/JSON。 |

| UI-04 | P0 | 前端静态资源随工具分发，界面不依赖外部 CDN。 |

## 3. 非功能与安全要求

| ID | 硬约束 |
| --- | --- |
| NFR-01 | 单向隔离；不回传内网库存、不做跨区自动传输，依合规渠道人工送入。 |
| NFR-02 | 密码不得进入命令行参数、日志或归档；提供安全非交互输入。 |
| NFR-03 | 记录真实用户/入口；尊重其 Nexus 实际权限，代表操作的凭据要保护并最小化。 |
| NFR-04 | 不持久化明文 Nexus 密码；重启/授权失效进入待授权或待处理状态。 |
| NFR-05 | 受控网络、TLS 或可信等效保护、未授权访问限制。 |
| NFR-06 | 防 ZIP 穿越、炸弹、非法路径、超大输入；不得执行归档脚本。 |
| NFR-07 | 可重试、尽可能幂等；区分已存在、冲突、失败、UNKNOWN，禁止静默覆盖。 |
| NFR-08 | 解析/下载/发布各阶段可诊断；任务级及文件级进度、结果可见。 |
| NFR-09 | 小规模服务任务持久化；单次失败不影响其他任务或已上传文件。 |
| NFR-10 | 外网双桌面 OS 可单机使用；内网浏览器免 CLI，Linux 无头支持服务/CLI。 |
| NFR-11 | Bundle 显式格式版本，不兼容版本清晰拒绝。 |

**四个独立维度**：①解析（完整/部分/失败）；②已知文件收集（齐/缺失/失败）；③离线可安装性（已在指定环境验证/未验证/已知阻碍）；④Nexus 导入（全部发布或一致跳过/部分/失败）。sdist-only、动态构建、本地编译、npm optional/peer、平台依赖、外部脚本/资源、Git/直接 URL/本地路径/workspace 等均需说明风险与影响。

## 4. MVP 验收场景（原编号不变）

| ID | 验收标准 |
| --- | --- |
| AC-01 | 单 PyPI 包与版本约束递归求解，输出环境依赖/文件，失败可定位。 |
| AC-02 | CPython 3.9/3.12 × Windows/Linux 四环境独立结果、物理文件去重、缺口报告。 |
| AC-03 | 普通包重新解析、重复运行缓存命中、可选历史解析复用。 |
| AC-04 | Python/npm 项目依赖输入、受支持锁文件优先、可手动重解析。 |
| AC-05 | npm scoped/optional/平台依赖与脚本风险，Registry 文件可收集，外部缺口显式。 |
| AC-06 | Bundle 往返验证，哈希/结构正确；损坏、缺失、非法路径拒绝。 |
| AC-07 | PyPI/npm 文件通过中心服务写入 Nexus Hosted，结果逐文件可查。 |
| AC-08 | 重复 Bundle 导入，相同内容跳过、内容冲突明确报错，不覆盖。 |
| AC-09 | 内网 Web/CLI 都能提交，任务 ID、状态、审计统一。 |
| AC-10 | Agent 无人值守完成认证、提交、等待、结构化报告/退出码。 |
| AC-11 | 网络故障、权限不足或服务重启，结果不丢，未知状态可追，安全重新授权/核实。 |
| AC-12 | 在完全无公网的受测客户端上，只用内网 Nexus 安装无需额外联网的代表包；未实测不宣称通过。 |

测试样本、平台、锁文件范围与 Nexus 版本由 `technical-validation.md` 记录。

## 5. 非目标、后续增强与待验证

**MVP 不做**：全站镜像、反向传输/自动跨区传输、合规流程绕过、非 PyPI/npm 内容（镜像/系统包/模型）、不可信脚本自动构建和成功保证、管理员审批/多租户、复杂角色系统、分布式任务/HA、Electron。断点续传、大规模并发、高级分卷、复杂终态文件级原地重试放 P1/P2。

**可选增强**：环境预设/模板、历史解析对比、细粒度缓存、任务取消/失败文件重试/并发控制、隔离式离线安装测试、受控源码构建、桌面壳与高级 Agent、合规前提下的传输优化。

**待验证边界**：Python 跨实现/版本/ABI/平台的 markers/tags；动态 `pyproject.toml`/构建后端与 lockfile 方言；npm lockfile/peer/optional/原生/脚本/特殊源；Nexus 身份与发布去重；真实用户长任务凭据；Bundle 大小/磁盘/超时/保留/并发；Schema/API/CLI 和具体工具链。**当前状态以 `technical-validation.md` 为准；待验证不等于设计决策已否定。**
